# Разработка и проверка

## Рабочий порядок

В Termux достаточно Git, GitHub CLI и Bash. Когда все локальные изменения относятся к задаче, отправьте их и дождитесь результата на GitHub:

```bash
bash scripts/push.sh "Описание изменения" && bash scripts/ci.sh
```

`scripts/ci.sh` можно повторно запустить после отправки. Он ищет запуск `push` для текущих ветки и коммита и выводит статус и ссылку. Если проверка упала, скрипт показывает журнал упавшего шага. Полные TAP-отчёты и патч форматирования доступны в артефакте `atlanta-cam-reports`.

Для ручной разработки с установленным Node.js:

1. Установите зависимости командой `npm ci` и запустите `npm run dev`.
2. Меняйте соответствующий модуль в `src/`, не итоговый HTML.
3. Запустите подходящие расчётные тесты, затем `npm run format`.
4. Перед выпуском выполните `npm test` либо `npm run package`.
5. Используйте HTML из `dist/`. ZIP формируется только после успешной полной проверки.

Для готовой программы установка Node.js не требуется. Интернет нужен разработчику при первой установке npm-пакетов и тестового Chromium. Готовый HTML не обращается к CDN или внешнему серверу.

## Инварианты данных

- Геометрия внутри приложения хранится в миллиметрах. Профиль FANUC задаёт коэффициенты вывода координат и подачи отдельно.
- Локальные `x/y` — плоскость чертежа, локальный `z` — углубление. Физические оси преобразуются через `core/planes.js`.
- Историческое значение `workPlane: "zx"` обозначает требуемое отображение XZ. Оно сохранено ради совместимости проектов; `planeInfo()` принимает также `"xz"`.
- G92 содержит физические X/Y/Z. Его нельзя преобразовывать как координаты плоского контура.
- `zReferenceEnabled`, `zReferencePlate`, `zReferenceSurfaceMode`, `zReferenceSurfaceZ` относятся к операции. Отсутствующий флаг в прежнем проекте означает выключенный режим; для новой операции режим включён. Производное значение поверхности в режиме `top` пересчитывается из геометрии и нуля, а сохранённое ручное значение не подменяется.
- `repeatMode`, `g25Shift`, `g25Reverse`, форма и рабочая длина фрезы относятся к операции и должны сохраняться вместе с ней.
- Восстановление проекта проверяет входные данные до замены открытого проекта. Сценарии ошибок должны сохранять прежнюю геометрию и NC.

## Тесты

`tests/unit/` запускается встроенным `node:test`. Здесь проверяются геометрия, плоскости, формы инструмента, обработка, адреса кадров и семантика команд из руководства.

`tests/fixtures/baseline-3.87.json` содержит 34 результата, полученных из версии 3.87 до выпуска рефакторинга. Проверяется полный текст NC и SHA-256 JSON всех движений, включая их параметры. Исходный SHA-256 версии 3.87 записан в этом файле. **Не пересоздавайте эталоны из новой реализации только ради прохождения тестов.** Изменение траектории должно иметь отдельное обоснование и проверенный ожидаемый результат.

`tests/browser/` проверяет собранный автономный HTML через Playwright. Каждый сценарий получает отдельный браузерный контекст; нет зависимости от личного localStorage или порядка запуска тестов. Проверяются расчёты, восстановление/сохранение, удаление пересечения и undo, автосохранение, повреждённые файлы, настоящий Worker, его запасной путь и отмена.

Для каждой открытой тестами страницы проверяется отсутствие необработанных ошибок JavaScript и внешних HTTP-запросов. Дополнительно сверяется дерево элементов и атрибутов интерфейса с 3.87, кроме нового раздела Z и начального выбора верхнего левого нуля; проверяются синтаксис автономной сборки и её контрольная сумма.

`z-reference.test.js` в расчётном и браузерном наборах проверяет новую привязку. `vlad-setup.test.js` сравнивает 2514 движений исходного примера и файла из `examples/`, используя физическую установку, описанную пользователем. Этот пример не служит эталоном для всех возможных установок инструмента.

Результат `npm test` записывается в `reports/verification.json`, подробные журналы — рядом. Снимок сценария XZ/G25 находится в `test-results/xz-g25.png`. Папки результатов исключены из обычного Git-индекса; релизный архив включает `reports/`.

## Сборка и переносимость

Скрипты используют пути от `import.meta.url`, передают аргументы процесса массивом и не требуют Bash или PowerShell. Проект можно переносить, в том числе в папку с пробелами и кириллицей. `npm ci` использует зафиксированный lock-файл.

Сборщик выдаёт синтаксис с целевой совместимостью Firefox 55; полифиллы прежнего приложения вынесены в `platform/compatibility.js`. Это не заменяет фактический прогон на старом браузере. Проверенная среда конкретного выпуска указана в протоколе.

Локальный сервер слушает только `127.0.0.1` и раздаёт `dist/`. Автономная страница сохраняет строгую политику CSP; версия разработки дополнительно разрешает загрузку собственных JS/CSS. Для отладки сборки при необходимости вручную подключите `app.js.map` в инструментах браузера.

## Дальнейшие технические шаги

При изменении крупного алгоритма добавляйте тест на его вход и результат, а затем выделяйте самостоятельную часть. Следующие разумные области декомпозиции — обработчики событий корней интерфейса и внутренние этапы `nc/controller.js`. Не смешивайте такую переработку с новым смыслом команд станка в одном изменении.

У проекта нет добавленной сторонней лицензии на исходное приложение: права автора не переопределялись. Лицензии пакетов разработки устанавливаются вместе с npm-зависимостями. Публикацию исходников и выбор лицензии следует согласовать с владельцем приложения.
